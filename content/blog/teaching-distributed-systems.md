# Teaching distributed systems with working artifacts

Students understand distributed systems more deeply when architecture, implementation, and failure analysis appear together in the same exercise.

Theory is essential, but it becomes durable when it is attached to an artifact that can be observed and changed. A small service graph, a queue-backed workflow, or a replicated state example gives students a concrete place to ask better questions.

## What changes in the classroom

When students can inspect real artifacts, discussions shift from abstract definitions toward engineering judgment:

- what should be retried and what should fail fast
- where a service boundary helps or harms
- how observability changes debugging quality

This is also one reason I value combining academic work with engineering practice. Each one sharpens the other.
